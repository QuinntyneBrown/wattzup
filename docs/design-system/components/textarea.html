Textarea

The textarea takes a few sentences: what went wrong on the ride, an idea, a thank-you. It is the text field's ink well, taller, with a counter when there is a limit.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use textarea.input when the answer may run past one line: the Send feedback message ("What went wrong?", "What could be better?", "What’s working for you?"). Use a text field for anything that fits on one line. Always inside a form field.

Anatomy

  1. Label.field__label; a question works well for open text.
  2. Text14px, line height 20px, 10px × 12px padding.
  3. ContainerSame well and border as .input; at least 112px tall (--space-28), about four rows; vertical resize.
  4. CounterOptional; .field__counter under the right edge.

Variants

Context is sent with your note.85 / 500
Plain with an example placeholder; with hint and counter; auto-grow (.input--autogrow, uses field-sizing: content where supported, capped at 12rem).
HTML
<textarea class="input" id="feedback-message" rows="4" maxlength="500"
  aria-describedby="feedback-hint feedback-count"
  placeholder="e.g. Resistance stayed at L8 when the video dropped to recovery."></textarea>

Sizes

One size: the textarea sets its height with rows (minimum 2; 4 in Send feedback) and never shrinks below --space-28 (112px) unless it auto-grows (minimum --space-20). Text is always 14px.

Disabled is the "Sending…" moment: the message cannot change while it is on its way. Invalid follows an empty submit or a message over the limit, with an error line ("Write a line about what went wrong, then send." or "Shorten this to 500 characters.").

Responsive behaviour

WidthRule
360 (base)Full width inside the bottom sheet; four rows keep the footer and Send in view above the keyboard. Resize is vertical only.
640 (sm)Inside the 25rem feedback popover; no change to the field.
1024 (lg)No change; never wider than its form column.

Theming

Reads the same --field-* tokens as text field. The ink well inside a panel (dark) or on a white panel (light) reads as recessed in both themes.

Accessibility

Role and pattern

Native <textarea> with <label for>. Hint and counter via aria-describedby; aria-invalid with an error line when invalid. Use maxlength only if the extra text would be lost; otherwise let it run over and show the counter in heart so pasted text is not silently cut.

Keyboard

KeyAction
TabInto and out of the textarea (Tab does not insert a tab character).
EnterNew line. It never submits the form.
Ctrl/⌘+EnterOptional shortcut to send, offered only alongside the visible Send button.

Focus

Same flush 2px ring as the text field. When the feedback panel opens, focus starts on the kind picker, not in the textarea, so the keyboard does not cover the panel on phones.

Labelling

The label changes with the feedback kind ("What went wrong?" / "What could be better?" / "What’s working for you?"); keep the id stable so the association holds. Announce the counter politely only in the last 50 characters.

Motion

Auto-grow resizes with the text, without animation.

Touch

The whole well is the target (at least 112px tall). The resize handle is a pointer nicety; touch users get auto-grow instead.

Content

  • Ask a question as the label when the answer is open: "What went wrong?".
  • The placeholder is one concrete example that starts with "e.g.": "e.g. Resistance stayed at L8 when the video dropped to recovery."
  • Counters read "85 / 500"; near the limit, the hint can say "16 characters left".

Drift fixed during extraction:

  • dialogs/feedback/*: .feedback__message uses a --color-line border (1.3:1) and resize: none; it becomes textarea.input (3:1 border, vertical resize).
  • dialogs/feedback/*: the textarea's line height is relaxed (1.625) where every other field is 20px; normalised to --line-height-sm.
  • dialogs/feedback/idea, kudos: the label and placeholder change with the kind but the message keeps the bug text (README open question 12); a kind change keeps what the rider typed, so this is expected, not drift.
