Badge

A word or two of status in a capsule: New best, Connected, Beta. Colour follows Telo Ride's meanings, and the words always carry them.

Overview

A badge is a short status label in a capsule: "New best", "Connected", "Beta". It is the kit's .pill (from docs/mocks/assets/ui.css) with five tones (gold, volt, heart, rest, ok) plus neutral; this page adds a warn tone, a count style and a leading dot. The mocks do not place a pill on any screen yet; the places that say the same things today are plain coloured text (Connect Bike's "Beta" in warn, Results' "+1 new star" in gold, Diagnostics' volt "Recording" with a dot), and those are what a badge replaces when a status needs to stand out in a row or card.

  • Badges are not buttons; for something to press, use a chip.
  • Tone follows Telo Ride's colour meanings: gold only for earned things, volt only for you, heart for lost or danger, rest for recoveries, ok for connected and done.
  • For a sentence of status use an inline message or an alert.

Anatomy

  1. Dot (optional)6px, currentColor; for live states (connected, recording).
  2. Label12px medium, one or two words, sentence case.
  3. Capsule--radius-full, 2 × 8px padding, a 15% tint of the tone over its surface (neutral: --color-raised).

Sizes

Badges have one size (12px label, 20px tall); the count style uses a 14px numeral inside the same height.

States

Badges are not interactive, so they have no hover, focus, active or disabled state of their own; they fade with a disabled parent. What changes is the surface under them, and the tint is mixed over that surface, so contrast moves with it.

Responsive behaviour

  • Badges never wrap (white-space: nowrap) and never truncate; at 360px a row with a badge truncates its title instead.
  • No breakpoint changes them.

Theming

Today the tones mix 15% of the tone colour into transparent: background: color-mix(in srgb, var(--color-gold) 15%, transparent), with the -fg text variant on top. That reads differently on every surface, and three tones miss 4.5:1 (table below). The fix is to read the status tokens the banners already use, which are checked in both themes:

.pill--gold  { background: var(--color-gold-subtle);   color: var(--color-gold-fg); }
.pill--volt  { background: var(--color-accent-subtle); color: var(--color-fg-accent); }
.pill--heart { background: var(--color-danger-bg);     color: var(--color-danger-fg); }
.pill--rest  { background: var(--color-info-bg);       color: var(--color-info-fg); }
.pill--ok    { background: var(--color-success-bg);    color: var(--color-success-fg); }
.pill--warn  { background: var(--color-warning-bg);    color: var(--color-warning-fg); }  /* added here */

Accessibility

Role and pattern

A <span> with text. No role. A count badge sets aria-label with its meaning ("6 of 10 seats taken"). A badge that appears because something changed ("Connected") is announced by the live region that reports the change, not by the badge.

Keyboard

KeyAction
TabSkips badges; they are not focusable.

Focus

None; badges never take focus.

Labelling

The label is the text. Dots are aria-hidden. Never use a badge without words (a coloured dot alone).

Content

  • One or two words, sentence case: "New best", "Lost the bike", "Beta".
  • Counts as "6 / 10" (seats) or "5 / 21" (stars), with a spoken label.
  • Say the state, not the colour: "Connected", never "Green".
  • Gold badges only for earned things: a new best, a star, a level.
