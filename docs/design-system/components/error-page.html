Error page

When a screen cannot work: say what happened, what is safe, and the one way forward.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

An error page replaces a screen that cannot work, says why in plain words, and offers one way forward. Telo Ride draws three in the mocks: not found (.not-found: "This page doesn’t exist." with Back to Home) and two browser panels (.browser-panel) over the custom ride, for a browser without Web Bluetooth ("Open Telo Ride in Chrome or Edge") and for plain http ("Open the secure version of this page"). .error-page is the not-found layout as a block, with an icon, a status line and a reference for failures we can trace; this page also sets the rules for offline and 500.

  • Full-screen error: the route cannot render (not found, a crash).
  • Panel error: one region cannot work in this browser (the ride dashboard without Bluetooth); the rest of the page stays.
  • Recoverable problems inside a working screen are alerts or inline messages, not error pages.

Anatomy

  1. Icon (optional)32px, heart for our failures, warn for the browser's; aria-hidden.
  2. Status line (optional)12px mono faint ("Error 500"); never on not found, which speaks for itself.
  3. Title.page__title: what happened, as a sentence with a full stop.
  4. Lead.page__lead: why, and that rides and progress are safe.
  5. ActionOne primary button (btn--lg); a second ghost action at most.
  6. Reference (optional)Build and time, so a bug report can find it.

Sizes

Error pages take the page or panel they replace. Full pages use the container and .page__title; panels cap at 28rem (--layout-panel-narrow).

States

The page is static; its actions carry the states. Copy link confirms in place ("Link copied") and announces it through a status region. Actions are never disabled on an error page: if there is nothing to do, say so and offer Home.

Responsive behaviour

  • 360px: not found keeps the 16px gutter; the title wraps; the button stays its natural width.
  • 640px: content caps at 36rem (--setup-form-max), left-aligned in the container.
  • 1024px: browser panels centre over the ride video; the resistance panel beside them stays visible but disabled.

Theming

.error-page { max-width: var(--setup-form-max); }
.error-page__icon--heart { color: var(--color-heart-fg); }
.browser-panel__icon { color: var(--color-warn-fg); }

The browser panels sit on the ride overlay's 90% ink scrim, so their text reads against ink in both themes.

Accessibility

Role and pattern

A full error page is the page: its <h1> is the title and the document <title> starts with it ("Page not found — Telo Ride"). A browser panel that blocks a region is role="alert" so it is announced when the dashboard loads. No APG widget.

Keyboard

KeyAction
TabSkip link, header, then the one action.
EnterRuns the action.

Focus

On a full page, focus starts at the top as usual. When a panel replaces a region the rider was using, move focus to its heading.

Labelling

Title says what happened; the lead says why and what is safe. Copy link announces "Link copied". The URL under the panel is plain text that can be selected.

Content

  • Say what happened in one sentence ("This page doesn’t exist.").
  • Reassure about what riders care about: "Your rides and progress are safe."
  • Name browsers and protocols exactly (Chrome, Edge, Safari, Firefox, HTTPS).
  • One way forward, named for where it goes ("Back to Home", "Open over HTTPS").
  • No blame, no jokes, no error codes in titles.
