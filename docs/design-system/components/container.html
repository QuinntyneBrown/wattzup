Container and grid

The pieces every page is laid out with: a centred container with responsive margins, the page block that gives it a title and breathing room, and four primitives (grid, split, stack, cluster) for what goes inside.

Overview

A Telo Ride screen is .app (a full-height column) → a header → .app__scroll → <main class="container page">. The container centres content and sets the side margins; the page block sets the vertical padding and holds the h1. Inside, most screens are a split: content on the left, a fixed aside on the right from 1024px (Profile's settings, Results' rewards, Race Setup's preview, the ride dashboard's bike control).

  • .container: max 1280px (--layout-container-max), margins 16 / 24 / 32px. Every mock page uses it.
  • .container--narrow (1024px) for a single column that still wants room, like Connect Bike; .container--form (768px) for a form that reads top to bottom.
  • .grid, .split, .stack, .cluster are additions that name what the mocks write by hand in each area's CSS.

Anatomy

  1. Margin--layout-margin: 16px, 24px from 640, 32px from 1024. The dashed outer line is the viewport.
  2. ContainerCentred, capped at --layout-container-max (1280px).
  3. Page titleh1.page__title: 24px semibold, 30px from 640, tight tracking.
  4. Lead.page__lead: 14px muted, 8px under the title.

Responsive behaviour

  • 360px: 16px margins, one column, page title 24px. A split stacks content above its aside (Results: the place, then what you earned).
  • 640px: margins 24px, title 30px. Tiles go from 2 to 4 across where the area asks (map tiles).
  • 1024px: margins 32px, gutters 32px, 12 columns; the split puts the aside beside the content; page padding grows to 40px.
  • Never write a breakpoint into a component when the layout tokens already change there; read --layout-gutter and --layout-margin.
  • Grid tracks are minmax(0, 1fr), never bare 1fr: a long word or a photo's minimum width must not push the page sideways (the Next ride card overflowed phones in the design for exactly this reason).

Theming

Primitives draw nothing; they read layout tokens only. The page takes --color-ink from .app; the title is --color-fg, the lead --color-muted.

Accessibility

Role and pattern

The container is <main id="main"> on every page (the skip link's target; APG landmark regions). A split's aside is an <aside aria-labelledby> naming its heading ("Settings", "What you earned"). Grids and stacks are divs; a set of like items is a <ul>.

Keyboard

KeyAction
TabFollows DOM order, which must match visual order: never reorder with order or grid placement in a way that makes focus jump.

Focus

Only .app__scroll scrolls, so the header never covers a focused element (2.4.11).

Labelling

One h1 per page, the .page__title; screens without a visible title (Race, Results, the lobby) get a visually hidden one.

Motion

None.

Touch

Reflow (1.4.10): every primitive collapses to one column at 320px with no horizontal scroll; spacing is in rem so it grows with the user's text size.

Content

  • Page titles are short and human: "Evening, Sam.", "Classes", "Maps". Sentence case; a greeting ends with a full stop, a section name does not.
  • A lead is one sentence that says what the page is for: "Ride a video alone whenever you like, or join a group of 8–10 riders. The bike follows the class either way." Keep it under two lines at 640px.
