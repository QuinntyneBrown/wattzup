Description list

Labels and values about one thing: how long this map is, where the XP came from, what the browser can see.

Overview

A description list pairs a label with a value about one thing: this map, this ride's XP, this connection. The mocks have four: Race Setup's facts (.setup-facts: small label over a big numeral), Results' XP earned (.xp-earned: reason left, gold sum right), Diagnostics' facts (.diagnostics__facts: label left, mono value right) and Custom workout's Your ride summary (.plan-preview__facts). .dl is the generic block with the two layouts they use.

  • Inline (.dl--inline): label left, value right; for 3–10 facts read as a list.
  • Stacked (.dl--stacked): label above a numeral; for 2–5 headline facts. When the numeral is the point, see Stat.
  • Comparing several things by the same facts is a table.

Anatomy

  1. Term (<dt>)14px (12px stacked) --color-muted, never wraps in the inline layout.
  2. Detail (<dd>)14px --color-fg, right-aligned inline; Barlow numeral (.dl__num) for numbers, mono (.dl--mono) for machine text.
  3. Tone (optional)data-tone="ok|warn|bad|gold" colours the value; the words still say the state ("Available", "None picked yet").

  • Loading: keep the term, put a text skeleton where the value goes, set aria-busy="true" on the list. The mocks never load (Diagnostics reads live browser state), so this is the rule for later.
  • Unknown values say why ("None picked yet", "0 this ride"), never a blank.

Responsive behaviour

  • 360px: inline lists keep two columns; long values (URLs, device IDs) wrap with overflow-wrap: break-word while terms stay on one line. Stacked facts wrap into two per row.
  • 640px: stacked facts fit four across (Race Setup).
  • 1024px: lists live in asides of fixed width (Results 400px, Custom workout 420px, Diagnostics 460px max) and do not grow.

Theming

.dl { --dl-label: var(--color-muted); --dl-gap-x: var(--space-6); --dl-gap-y: var(--space-2); }
.dl dd[data-tone="warn"] { color: var(--color-warn-fg); }

Tone colours use the -fg text variants, which deepen on paper (amber-deep, red-deep, green-deep) so a toned value passes 4.5:1 in both themes.

Accessibility

Role and pattern

Native <dl> with <dt>/<dd>; groups may be wrapped in <div> (valid HTML). No ARIA role. Screen readers announce the list and its pairs.

Keyboard

KeyAction
TabSkips the list unless a value contains a link.
EnterFollows a link inside a value.

Focus

Only links inside values take focus, with the shared ring.

Labelling

The term labels the value; do not repeat it inside the value. Units are words or symbols screen readers know ("km", "dBm", "ms"). A minus sign is U+2212 ("−61 dBm") so it is read as minus. Tone is never the only signal: "None picked yet" says what warn means.

Motion

None. Values that update live (Diagnostics connection time) change in place without animation and are not live regions; they would chatter.

Touch

Not interactive. Links inside values use the 24px minimum target.

Content

  • Terms: short nouns in sentence case ("Last command", "Peak resistance"); no colons.
  • Values lead with the answer, then detail after " · " ("Connected · 6m 52s").
  • Numbers with units take a space ("14.2 km", "41 ms"); approximations use "~" ("~154 W").
  • XP lines: the reason as the rider would say it ("84% on target", "4-day streak"), the value signed ("+67").
