Form field

A form field stacks a label, a control and the words that help with it. Every text field, textarea, select and slider in Telo Ride sits in one, so labels, hints and errors look and announce the same everywhere.

Overview

.field is a layout primitive, not a control. Wrap one control in it with its .field__label, then optionally a .field__hint, a .field__error and a .field__counter. Groups of checkboxes or radios use a fieldset (.choice-group) instead, because they need one label for many controls.

In the mocks the same parts appear under area names: the feedback panel's "What went wrong?" (.feedback__label), Custom Setup's "YouTube link" (.video-sync__label) and "Ride 0:00 starts at". New screens use .field.

Anatomy

  1. Label<label for>, 14px medium --color-muted. Always visible; never a placeholder.
  2. ControlText field, textarea, select or slider; 6px below the label (--space-1-5).
  3. Hint or error12px; hint in --color-faint, error in --color-heart-fg with an alert icon; linked by aria-describedby.
  4. Counter (optional)12px tabular figures, right-aligned in .field__footer; turns heart when over.

Responsive behaviour

WidthRule
360 (base)Label above control, full width of the form column. Hints and errors wrap under the control; the counter stays on the right of the footer row.
640 (sm).field--inline puts the label in a 1fr column beside a 1.5fr control. Use it only for short controls in settings-style lists.
1024 (lg)No change; the form column is capped (Custom Setup: 36rem), so fields never stretch past a readable width.

Theming

The field reads semantic tokens directly: --color-muted for the label, --color-faint for hints and counters, --color-heart-fg for errors. Its control owns the --field-* tokens (see text field). The dark error text was raised from the fill red (#e5194b, 3.9:1 on panels) to --palette-red-light.

Accessibility

Role and pattern

Native labelling: <label for> pointing at the control's id. Hint, error and counter are linked with aria-describedby (error first when both show). Invalid controls set aria-invalid="true". No ARIA widget pattern applies; see WAI's Labeling controls tutorial.

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the control; the label, hint and counter are not focusable.
Click on labelFocuses the control (pointer convenience that for gives for free).

Focus

The control takes the ring (2px, offset 0 so it hugs the border). After a failed submit, focus goes to the error summary, whose links move focus to each field.

Labelling

Every control has a visible label that says what to enter ("YouTube link", "What went wrong?"). Optional fields say "(optional)" inside the label; required is the default and is not marked with an asterisk. The counter is announced as part of the description; announce it live only near the limit ("20 characters left") so it does not chatter on every key.

Motion

Errors appear without animation; nothing moves the layout except the error line itself, which pushes content down by one line.

Touch

The label is part of the target (it focuses the control). Controls are 40px tall; keep 24px between fields (--form-gap).

Content

  • Labels are nouns or short questions in sentence case, no colon: "YouTube link", "What went wrong?".
  • Hints say what happens or what format works: "Plays in sync on the dashboard."
  • Errors say what is wrong and how to fix it, in one sentence: "That isn't a full YouTube link. Paste the address that starts with https://www.youtube.com/watch?v=". Never "Invalid input".
  • Placeholders show an example ("e.g. Resistance stayed at L8 when the video dropped to recovery."), never the label.
