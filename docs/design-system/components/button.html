Component · Actions

Button

Buttons make something happen: go to the start line, join a group, pause the ride, report a bug. One volt primary per view tells the rider what the screen is for; gold is kept for the moment a map unlocks.

Overview

Use a button when pressing it changes something: it starts a ride, saves, pairs the bike, opens a dialog or ends a session. Use a link when it only goes somewhere else (Home's "All maps →"). Use a menu when one trigger offers several actions, and a button group when the buttons pick one option from a set.

  • Primary (volt fill, ink label) is the one action the view exists for: "Go to the start line", "Start ride", "Pair Echelon EX-5s". Never two per view.
  • Light (bone fill) is the stronger of two equal choices sitting side by side, like Home's "Join group" next to a quiet "Ride alone".
  • Gold is only for an earned unlock: "Ride it" on the unlock banner, "Ride Neon Docklands" on the results unlock card.
  • Raised is the everyday secondary on panels and headers: "Pause", "Copy link", "Download packet log", "Discard and open library".
  • Outline is a secondary on the bare page where a raised fill would look like a card.
  • Quiet is the low-emphasis choice: "Ride alone", "Keep riding".
  • Danger confirms a destructive action inside a confirmation. Quiet danger is the muted "End" and "Leave" that only turn red on hover.
  • Icon button (.icon-btn) is the square, label-less control in headers: "Full screen", "Close feedback".

Anatomy

  1. LabelInter Tight 14px semibold (16px from --lg); a verb phrase in sentence case. It is the accessible name.
  2. Icon (optional)16px lucide, leading for a verb ("Copy link"), trailing for a direction ("Race Old Town Criterium →"); aria-hidden; 8px gap.
  3. ContainerHeight --btn-height (40px), 16px side padding, --radius-lg (12px radius from --lg), 1px border that only outline uses.

Variants change emphasis, not meaning. Every variant only sets the --btn-* tokens; .btn reads them.

Loading: two shapes

Block buttons change their label to the present progressive with a leading spinner (Connect Bike "Pairing…"). Inline buttons keep the idle label in flow, hidden, under the spinner, so the width holds.
HTML
<button class="btn btn--primary btn--xl btn--block" type="button" disabled aria-busy="true">
  <svg class="icon icon--lg icon--spin" aria-hidden="true">…</svg>Pairing…
</button>

<button class="btn btn--primary btn--sm" type="submit" disabled aria-busy="true">
  <span class="btn__label">Report bug</span>
  <svg class="icon btn__spinner" aria-hidden="true">…</svg>
</button>
  • Loading sets aria-busy="true" and disabled together, so a second press does nothing; the button stays fully opaque (it is working, not off) and the status is announced by the surrounding live region ("Sending your report…"), not by the button.
  • Disabled fades to 40%. Prefer an enabled button that explains the problem when pressed; disable only when the reason is on screen (Class Start's "Join" is disabled under the "Open Telo Ride in Chrome or Edge" notice).
  • Pressed and expanded are for icon buttons that toggle (full screen) or open a menu; both share the raised fill.

Responsive behaviour

WidthRule
360 (base)Setup columns end in an .btn--xl .btn--block start action. Pairs of actions in a popover stack full width ("Leave this ride?" stacks Save, Discard, Keep riding). Ride header buttons grow to 48px (--target-ride) because they are pressed mid-ride.
640 (sm)Ride header buttons return to the design's 40px. Dialog footers put actions on one row, primary last.
1024 (lg)The setup start action sits at the bottom of its column (margin-top: auto); block buttons are capped by their column (420px aside), never by the viewport.
  • Labels never truncate or wrap; a label that wraps at 360px is too long. "Save ride and open library" is the longest in the product and fits a 320px popover.
  • Icon-only buttons keep their 36px square at every width; on phones they sit in rows tall enough that the row is the 44px target.

Theming

The button reads only component tokens declared on .btn: --btn-bg, --btn-bg-hover, --btn-fg, --btn-fg-hover, --btn-border, --btn-height, --btn-pad, --btn-radius, --btn-font-size, --btn-line-height, --btn-weight and --btn-hover-opacity. Each variant points them at semantic tokens; a theme changes the semantic tokens; a one-off re-skin overrides the component tokens and never the properties.

/* The Library popover's quiet "Keep riding" (from .ride-leave__keep), as tokens */
.btn.ride-leave__keep { --btn-height: var(--control-height-sm); --btn-weight: var(--font-weight-medium); --btn-fg: var(--color-muted); --btn-fg-hover: var(--color-fg); }

Volt and gold are the same in both themes (orange and gold fills with an ink label read at 6:1 and 11:1 either way). The light theme flips raised to paper-raised, bone to ink for .btn--light, and deepens the danger fill to --palette-red-deep so its label stays above 4.5:1.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form. When the action navigates ("Go to the start line" opens the lobby), it is an <a class="btn" href>: it looks like a button and behaves like a link. Toggles add aria-pressed; menu triggers add aria-haspopup="menu" and aria-expanded. See the APG Button pattern.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order. Disabled buttons are skipped.
EnterActivates a button or a button-styled link.
SpaceActivates a <button> on key up (a link ignores Space, which is why navigation stays a link).
EscNo effect on the button; in the Library popover it closes the popover and returns focus to "Library".

Focus

The shared ring: 2px --color-focus-ring (signal orange in dark, --palette-signal-deep in light) at a 2px offset on :focus-visible. The offset gap shows the surface, so the ring stays visible around a volt primary. When a popover opens, focus lands on its first action ("Save ride and open library" has autofocus).

Labelling

The visible label is the name. Icon-only buttons carry aria-label and a matching title ("Full screen", "Close feedback", "Leave class"). A loading button keeps its name ("Report bug") and adds aria-busy; progress is announced by a role="status" region near it. A button whose label hides on phones (the class ride's "Pause") keeps an aria-label.

Motion

Fill and colour ease over --duration-fast (150ms); pressing scales to 0.98. Reduced motion zeroes the durations, so both are instant. The spinner is a status indicator; under reduced motion it stops on its arc and the label or live region still says what is happening.

Touch

Every size clears the 24px minimum; medium and up clear 40px. Mid-ride buttons are 48px on phones (--target-ride). Hover-only cues (quiet danger turning red) are never the only signal: "End" carries its stop icon and label.

Content

  • Verb first, sentence case, what happens next: "Go to the start line", "Pair Echelon EX-5s", "Use video's current time". Never "OK", "Submit" or "Click here".
  • Name the thing when the view holds several: "Race Old Town Criterium", "Ride Neon Docklands", "Report bug".
  • Destructive labels say what is lost: "Discard and open library", not "Confirm".
  • Loading labels use the present progressive with an ellipsis character: "Pairing…", "Sending…".
  • Times inside labels follow the content rules: "Join · starts in 9 min".
