App header

The bar across the top of every screen. On the four home screens it carries the brand, the main nav and who you are (bike, streak, level); inside a flow it slims down to the brand, where you came from and how to get out.

Overview

Telo Ride has no sidebar: navigation is one top bar. Which header a screen gets depends on whether the rider is choosing or doing.

  • App header (.app-header) on Home, Race (Map Select), Classes (Class Library), Profile and the 404. It holds the main nav and the rider's status. Use it on any screen reachable from the main nav.
  • Task headers on screens that are a step in a flow: Race Setup (.setup-header, "← Maps"), Class Start and Class Ride (.class-header), Results (.results-header), the race lobby (.race-lobby__header, "Leave"), Custom workout (.training-header, "Close") and the custom ride (.ride-header). They drop the nav so the only ways out are the ones the flow allows.
  • Not a header: the race's top bar over the 3D world is HUD glass; see HUD panel. .ride-header--ghost is a placement helper for the ride's popovers; see Popover.

Use tabs for views inside a page, never a second row of header links. For deep settings-like screens the system has a sidebar navigation the product does not use yet.

Anatomy

  1. BrandThe lockup inside a link named "Home"; 26px mark, 24px wordmark.
  2. Main nav<nav aria-label="Main">, four links, the current one aria-current="page" on a raised fill. A full-width row of its own below 640px.
  3. Bike statusBluetooth icon in volt (connected) or heart (off) and the bike's name. Static text, from 1024px.
  4. StreakFlame in warn and a Barlow numeral. Absent until the rider has a streak.
  5. LevelGold level badge plus the XP bar and "1,840 / 2,600 XP" from 640px; one link to Profile.
  6. Full screen36px .icon-btn, pulled 8px into the right margin (--edge).
  7. Bar10px top and bottom, 16 / 24 / 32px sides, 24px between groups, hairline --color-line under it. 56px tall when it fits on one row.

Variants

One app header and six task headers. They share the bar (padding, hairline, 36px controls) and differ in what sits between the brand and the end.

  • Current is the only nav state that changes the fill: raised behind fg text. Hover only lifts the text from muted to fg. Press adds nothing; the colour holds.

Responsive behaviour

The header is mobile first and changes at three widths. The frames below load the real mocks in their own viewport, so their media queries fire at the width shown (scroll sideways inside the strip).

WidthApp headerTask headers
Under 640pxBrand left, streak + level badge + full screen right; the nav drops to its own full-width row underneath (order: 99), four equal links. No XP bar, no bike.16px sides. Context text truncates with an ellipsis; the Class Ride header drops "/ 30:00" and Pause's label, and below 384px the wordmark (the mark stays). The custom ride's End and Pause grow to 48px.
640px (--layout-breakpoint-sm)The nav moves inline after the brand; the XP bar and its label appear beside the badge; sides 24px.24px sides; the ride header's divider appears.
1024px (--layout-breakpoint-lg)The bike status appears; sides 32px.32px sides.
  • The header never scrolls with the page: .app is a full-height column and only .app__scroll scrolls, so nothing needs position: sticky and nothing is covered (2.4.11).
  • Labels never wrap inside a link (white-space: nowrap); if a row is too wide the bar wraps between groups instead.

Theming

The bar has no fill of its own: it sits on the page's --color-ink with a --color-line hairline. Text is --color-muted, lifting to --color-fg; the current link is --color-raised. Status colours mean one thing each: volt for a connected bike, heart for one that is not, warn for the streak flame and gold only for level and XP (earned things). In light, the same roles resolve to paper, ink and the deeper -fg accents.

/* A quieter header for a kiosk build: no hairline, current link outlined */
.kiosk .app-header { border-bottom-color: transparent; }
.kiosk .app-header__nav-link[aria-current="page"] { background: none; box-shadow: inset 0 0 0 1px var(--color-line-strong); }

Accessibility

Role and pattern

A <header> that is a direct child of the app, so it is the page's banner landmark, holding a <nav aria-label="Main"> (APG landmark regions). Links are links, the full-screen control is a button. The custom ride's Library and Feedback open popovers and carry aria-haspopup="dialog" and aria-expanded.

Keyboard

KeyAction
Tab / Shift+TabBrand → nav links → level → full screen, in DOM order (which is visual order at every width; the nav's order: 99 below 640px puts it last visually but the DOM keeps it second, so the skip link and landmarks matter there).
EnterFollows a link; opens a ride menu popover.
Enter, SpaceToggles full screen.
EscLeaves full screen (the browser's own key) and closes an open ride popover, returning focus to its link.

Focus

The shared 2px --color-focus-ring at 2px offset on :focus-visible. Links in the bar have rounded corners (--radius-lg, --radius-md, --radius-full on the level link) so the ring follows the control. The skip link comes before the header on every page.

Labelling

  • The brand link is named "Home"; its lockup is decoration inside it.
  • The level link's name says everything the badge and bar show: "Level 7, 1840 of 2600 XP"; its children are aria-hidden.
  • The bike status reads "Echelon EX-5s connected" / "not connected" through visually hidden text, never colour alone.
  • The streak reads "4-day streak" through visually hidden text; the numeral is aria-hidden. (The mocks put aria-label on a plain <span>, which screen readers ignore; see Sources.)
  • Icon-only buttons have aria-label ("Full screen", "Leave class") and a tooltip.

Motion

Link and button colours ease over --duration-fast (150ms); nothing moves. Reduced motion zeroes the duration.

Touch

Nav links and icon buttons draw 36px tall, and the brand and nav links take touches across at least 44px through an invisible ::after that overhangs them (--target-comfortable); below 640px each nav link takes a quarter of the row (at least 80px wide). The level link is a 32px disc plus the bar. Mid-ride controls in the custom ride header grow to 48px (--target-ride) below 640px; on desktop the design keeps 36–40px (open question 9 in the mocks).

Content

  • Nav labels are single nouns for places: Home, Race, Classes, Profile. Never verbs, never icons alone.
  • Back links name where they go: "← Maps", "← Classes". Never "Back".
  • Context lines put the thing first, then how: "Old Town Criterium · vs Bots", "Old Town Criterium · 14.2 km · Riders online". Separate with a middle dot.
  • Exits say what they do to the ride: Close (nothing started), Leave (a lobby or class you joined), End (saves the ride). Library asks first because it would abandon a ride.
  • Numbers use Barlow numerals and thousands separators: "1,840 / 2,600 XP", "6:52 / 30:00".
