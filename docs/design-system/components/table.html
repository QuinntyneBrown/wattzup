Component · Data display

Table

Tables line facts up so people can compare across rows: which map, how many stars, what best time. One real table in the mocks, and the generic one every later screen uses.

Overview

A table compares the same facts across rows: maps by distance and best time, connection facts by value. Telo Ride has one in the mocks, Profile's Maps table (.map-table: map, stars, best), and this page adds the generic .table for everything after it: a caption, scoped headers, sortable columns, a dense size, row hover and current row, skeleton rows while loading, an empty row, and a wrapper that scrolls wide tables on their own.

  • Use a table when people read across a row and down a column: "which map has my slowest best?"
  • Use a list when each row is one thing to open (Map Select's path, recent rides).
  • Use the leaderboard for race and class standings: a ranked list with the rider's own row in volt, not a table.
  • Use a description list for one record's key-value facts (Diagnostics, Race Setup).

See Data tables and lists for density, sorting and the responsive strategy.

Anatomy

  1. Caption.table__caption: the table's name (semibold 16px) and an optional muted detail line. It is the accessible name.
  2. Column headerth scope="col": 12px semibold overline in --color-muted, over a full-strength hairline.
  3. Sort control.table__sort: a <button> inside the header; the <th> carries aria-sort. The chevron turns volt when sorted.
  4. Row headerth scope="row": the thing the row is about (the map), medium weight.
  5. Numeric cell.table__num: Barlow Condensed bold, tabular figures, right-aligned so digits line up.
  6. Scroll wrapper.table-wrap: panel, hairline, --radius-xl; role="region" + label + tabindex="0" so keyboard users can scroll it.

Sizes

Two densities. Default cells are 12 × 16px (rows about 44px), dense cells 8 × 12px (about 36px). The Profile maps table sits between them: 10px vertical, no horizontal padding, because it lives inside a section that already has its gutter.

  • Sorted: aria-sort="ascending|descending" on exactly one <th>; the others carry none (or none). Activating a sorted header flips it.
  • Current: aria-current="true" (the map you are on). Selection with checkboxes needs role="grid" and aria-selected; Telo Ride has no bulk actions, so it has no selectable tables yet.
  • Disabled rows do not exist: a locked map keeps its row, its name becomes a disabled button with a lock, and the row text turns muted.
  • Loading: aria-busy="true" on the table, skeleton cells, one polite announcement. Empty: one row spanning every column.

Responsive behaviour

  • 360px: tables of three columns or fewer (the Profile maps table) fit; anything wider goes in .table-wrap, whose .table keeps a --table-min-width of 36rem and scrolls sideways inside its own frame. The page never scrolls horizontally.
  • 640px: five-column tables (best times) fit without scrolling; the dense unlock table still scrolls its last column.
  • 1024px: tables sit in the main column of the two-column layouts (Profile, Results) and never stretch past it; long text cells wrap, numeric cells never do (white-space: nowrap).
  • Do not turn a table into cards on phones: every table in Telo Ride is narrow enough to scroll, and cards lose the column comparison.
  • The sticky header only works inside a wrapper with its own height; on a page that scrolls as a whole, leave .table--sticky off.

Theming

The table reads only semantic tokens through its component tokens. A theme swaps the semantics; a re-skin overrides the component tokens on .table.

.table {
  --table-head-fg: var(--color-muted);
  --table-border: color-mix(in srgb, var(--color-line) 60%, transparent);  /* the design's border-line/60 */
  --table-row-hover: var(--color-raised);
  --table-row-selected: var(--color-accent-subtle);
  --table-row-selected-edge: var(--color-volt);
}
/* A table on a raised well (inside a dialog) */
.dialog .table { --table-row-hover: var(--color-raised-hover); }

Dark (the design) puts the table on --color-panel (#15171b) with bone text; light puts it on a paper panel with ink text and the deeper accent (--color-volt-fg = signal-deep) for the sorted chevron, so it stays above 4.5:1.

Accessibility

Role and pattern

Native <table> with <caption> (or aria-labelledby pointing at the section heading), <th scope="col"> and <th scope="row">. Sorting follows the APG sortable table: a button in the header, aria-sort on the header cell. Not a grid: arrow keys do not move between cells.

Keyboard

KeyAction
Tab / Shift+TabMoves through the links and sort buttons in reading order, then to the scroll region when the table overflows.
Enter, SpaceOn a sort button: sorts by that column, or reverses it if it is already sorted.
← →With the scroll region focused: scrolls the table sideways.
EnterOn a map link: opens its Race Setup.

Focus

The shared ring (2px --color-focus-ring, 2px offset) on links and sort buttons; the scroll region draws its ring with no offset so it is not clipped by the page. Sorting keeps focus on the header button that was pressed.

Labelling

The caption is the name ("Your best times"). Hidden headers are still headers: the Profile table keeps a visually hidden <thead>. Star cells are role="img" with "3 of 3 stars". A dash for "no value" is aria-hidden with a visually hidden "No best yet" beside it. Locked rows add ", locked" to the button name. When a sort changes, announce "Sorted by best, fastest first" in a polite live region.

Motion

Row hover fades its fill over --duration-fast (150 ms); skeleton cells pulse over --duration-pulse. Under prefers-reduced-motion both stop (the tokens zero the durations) and skeletons hold a flat raised fill.

Touch

Rows are at least 40px tall; the map link fills its cell so the whole name is the target. Sort buttons are at least 24 × 24px with 16px between neighbours. Hover reveals nothing that touch would miss.

Content

  • Caption: a noun phrase in sentence case ("Your best times", "Unlock order"); an optional detail line says how it is sorted.
  • Headers: one or two words, sentence case in the source ("Best", "Climbing"); the overline style uppercases them visually.
  • Numbers: times as m:ss or h:mm:ss with no unit ("27:10"); distances with a space and unit ("14.2 km", "1240 m", as Map Select writes them); right-aligned.
  • Missing values: an en dash, never "0:00" or "N/A", and a spoken "No best yet".
  • Empty: say what fills the table and how ("No best times yet. Finish a race and its time shows up here.").
  • Ratings use the map's own words: Easy, Moderate, Hard, Brutal.
