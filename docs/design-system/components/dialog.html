Dialog

A modal surface for a short task the rider must finish or cancel before going on. Below 640px it rises from the bottom as a sheet; from 640px it sits centred over a scrim.

Overview

Telo Ride opens three modal surfaces: Diagnostics (connection facts and the packet log, from Profile and the ride), Send feedback (from the header's Feedback button) and Leave this ride? (from Library mid-ride). Each is its own panel in the mocks; this page gives them one shell, .scrim + .dialog, and one set of parts.

  • Use a dialog when the task is short, blocks what is behind it, and has a clear end: send, save, close.
  • Use a popover when the choice belongs to the button that opened it and the page should stay visible (Leave this ride, and Send feedback from 640px, are popovers on wide screens).
  • Use a page when the task has steps, needs a URL, or is longer than one screen (Connect Bike, Custom workout).
  • Never open a dialog on top of a running ride without pausing it first; Leave this ride says "The ride is paused while you decide."

  • Busy: aria-busy="true" on the dialog; the send button is aria-disabled + aria-busy and reads "Sending…" on its usual volt fill (focus stays on it), the other controls wait (close included, so a half-sent note is not lost), and a hidden role="status" says "Sending your feedback…".
  • Invalid: the field gets aria-invalid and an error tied by aria-describedby; focus moves to the field. The primary stays enabled so pressing it explains the problem.
  • Done: the body is replaced by a role="status" confirmation; the title changes ("Feedback sent") and focus goes to Done.
  • Error (send failed): keep the note, show an inline alert above the footer: "Couldn’t send. Check your connection and try again."

Responsive behaviour

  • Under 640px: a bottom sheet, full width, top corners rounded 24px, max 90% of the viewport tall; the footer sticks to the bottom and pads for the home indicator (env(safe-area-inset-bottom)).
  • From 640px (--layout-breakpoint-sm): centred, fully rounded, min(--dialog-width, 100vw − 32px) wide.
  • Long content scrolls inside the dialog; the page behind never scrolls (overflow: hidden on the scroller while open).

Theming

Block tokens: --dialog-bg (--color-panel), --dialog-border (--color-line), --dialog-radius (--radius-2xl), --dialog-width. The scrim is --color-scrim in both themes, so the page dims the same way on paper. The sticky footer reads --dialog-bg so it stays opaque over scrolled content.

Accessibility

Role and pattern

APG Dialog (Modal): role="dialog" with aria-modal="true" and aria-labelledby its title; everything else on the page gets inert (the mocks wrap it in <div inert aria-hidden="true">). A native <dialog> with showModal() gives the same and is preferred in the build.

Keyboard

KeyAction
Tab / Shift+TabCycles through the dialog's controls only; wraps at the ends.
EscCloses (the same as the safe choice: Keep riding, Close feedback). Ignored while busy.
EnterActivates the focused button; in a form, submits it.
← →Moves between feedback kinds (a radio group, roving tabindex).

Focus

  • On open: the first thing to act on. Leave this ride: Save ride and open library (autofocus, as in the mock). Send feedback: the message. Diagnostics: the dialog's title (tabindex="-1") because it opens to read.
  • On close: back to the button that opened it (Library, Feedback, the wrench on Profile).
  • The shared 2px ring; the textarea draws it inside its border (outline-offset: 0).

Labelling

Title names the dialog. The close button names what closing means ("Close feedback", "Keep riding"), never just "X". A confirmation's body can be the description (aria-describedby) so it is read on open.

Motion

Scrim fades in and the dialog fades with a 2% scale over --duration-base, --ease-panel; closing is instant. Reduced motion: no animation. No slide-up for the sheet; it is already where the thumb is.

Touch

Footer buttons 36–40px with 8px gaps; the stacked footer gives 40px full-width targets. The sheet never needs a drag handle: it closes with its button or Esc, not a swipe only.

Content

  • Title: a question for a decision ("Leave this ride?"), a noun for a tool ("Diagnostics"), a verb for a form ("Send feedback").
  • Body: the facts the decision turns on, with figures: "You’re 6:52 in with 2.24 km ridden."
  • Buttons say what happens: "Save ride and open library", "Discard and open library", "Keep riding"; never "OK" / "Cancel".
  • Done states thank and say what happens next: "Thanks — we’re on it." "If we need more detail, we’ll email you."
