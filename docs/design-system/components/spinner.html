Spinner

A short wait with no known end, always with words: Looking for bikes nearby…, Pairing…

WCAG 2.2 AAStatus: stableSince v1.0

Overview

A spinner says "working on it" when the wait is short and has no known length. In Telo Ride it is lucide's loader arc turning on .icon--spin (the kit also names it .spinner), and it appears in two places in the mocks, both on Connect Bike: searching ("Looking for bikes nearby…" with the volt spinner) and pairing (inside the disabled "Pairing…" button with aria-busy="true"). It always comes with words.

  • Use it for waits of about 1–10 s tied to one control or row (pairing, searching, saving).
  • For a longer wait with a known end, use a progress bar.
  • Do not use it for page loading: every screen reads local data and draws at once (see skeleton).

Anatomy

  1. SpinnerThe loader arc (M21 12a9 9 0 1 1-6.219-8.56) at the icon size, in --color-volt-fg, turning once per --duration-loop (1 s), linear.
  2. WordsWhat is happening, present tense, ending in an ellipsis; announced through role="status" or the button's aria-busy.

Sizes

The spinner takes the icon sizes: 14px (small buttons, dense rows), 16px (buttons), 20px (rows, the searching line, xl buttons), 24px (blocks). Never larger: a big spinner reads as a stalled page.

States

A spinner is itself a state: the loading state of the thing it sits in. A busy button stays disabled, so hover, focus and press do nothing; it keeps focus if it had it, so the ring stays where the rider left it.

Responsive behaviour

  • Spinners never change size with the viewport.
  • 360px: block buttons keep the spinner beside the label; long labels truncate after the spinner.
  • 640px and 1024px: no change.

Theming

.icon--spin { animation: icon-spin var(--duration-loop) linear infinite; }
.spinner-inline .icon--spin { color: var(--color-volt-fg); }
/* inside a button the icon keeps currentColor, the label colour */

Volt is "you": the spinner is your bike being found. On a primary button it takes the button's label colour instead.

Accessibility

Role and pattern

The SVG is aria-hidden. Its words sit in role="status" (polite), or the button carries aria-busy="true" and changes its label ("Pairing…"). No APG widget; see the aria-busy state.

Keyboard

KeyAction
TabA busy button stays in the tab order only if it already had focus; otherwise disabled buttons are skipped.

Focus

Focus stays on the busy button. When the wait ends, focus moves to what appeared (the paired card's Start button) or stays put.

Labelling

Announce the start ("Looking for bikes nearby…") and the end ("Paired with Echelon EX-5s."). Never announce on each turn.

Motion

One turn per second, linear. Under prefers-reduced-motion the loop duration becomes 0 and the reset stops animations, so the arc holds still; the words and aria-busy still say it is working.

Touch

Not a target; the busy button keeps its full size so nothing shifts.

Content

  • Present tense with an ellipsis: "Looking for bikes nearby…", "Pairing…", "Saving packet log…".
  • Name the thing: "Pairing…" on the button, then "Paired" with a check.
  • After about 10 s, add a reason or an action ("Not in the list? Close the Echelon app on your phone.").

Drift fixed during extraction
