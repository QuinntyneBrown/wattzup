Text field

The text field takes a short typed answer: a YouTube link, a video offset, a cadence. It is an ink well with a strong hairline so it reads as a place to type on any surface.

WCAG 2.2 AAStatus: stableSince v1.0

Overview

Use .input for one line of free text or a number the rider types. Always inside a form field with a visible label. For several lines use a textarea; for a number nudged in steps (minutes, rpm, resistance) prefer a number stepper or slider; for a fixed list use a select.

Pick the right type and inputmode so phones show the right keyboard: type="url" for the YouTube link, inputmode="decimal" for "0:12.0", inputmode="numeric" for whole numbers.

Anatomy

  1. Leading icon (optional)16px --color-muted, decorative, 12px from the edge.
  2. Value / placeholder14px --color-fg; placeholder in --color-faint as an example.
  3. Action (optional)A 36px .icon-btn inside the end: clear, show.
  4. Container40px tall, --field-bg ink well, 1px --field-border (3:1), --field-radius 8px, 12px padding.

Sizes

--control-height-sm/md/lg; large also steps the text to 16px and the padding to 16px. Custom Setup's YouTube link is 44px (--target-comfortable); new screens use md or lg.

  • Hover lifts the border from --color-line-strong to --color-muted.
  • Focus draws the 2px ring flush with the border (offset 0).
  • Read-only fills raised with a hairline border: it can be selected and copied but not changed; its focus ring is dashed.
  • Invalid uses the heart border and always comes with an error line under the field.
  • Disabled fades to 40%; prefer read-only when the value still matters to the rider.

Both themes

Responsive behaviour

WidthRule
360 (base)Full width of the form column. Long values (a YouTube URL) scroll inside the field; addons never shrink and keep their text on one line. Text stays at least 14px; iOS zooms inputs under 16px on focus, so pages that are mostly typing use --lg.
640 (sm)Short values (rpm, an offset) get a max width that fits the expected value plus room, not the whole column.
1024 (lg)Capped by the form column (36rem on Custom Setup).

Theming

.input declares --field-bg (ink), --field-border (--color-line-strong), --field-border-invalid (--color-heart) and --field-radius; states and variants re-point them (.input--raised sets --field-bg to raised). The ink well sits one step below panels in dark and below white panels in light (paper), so it reads as recessed in both.

Accessibility

Role and pattern

Native <input> with a <label for>; no ARIA widget pattern. Use autocomplete where it applies (url), spellcheck="false" for IDs, aria-invalid plus aria-describedby for errors.

Keyboard

KeyAction
TabInto the field, then to its action button (clear), then on.
EnterSubmits the form the field is in (native).
EscClears a search-type field (native); otherwise no effect.

Focus

2px --color-focus-ring at offset 0, flush with the border; read-only fields use a dashed ring. The clear button returns focus to the field after clearing.

Labelling

Visible label via for. Addon text ("rpm") is visible but not part of the name: add it to the label or to aria-describedby ("Cadence goal, rpm"). The clear button is named for its field: "Clear YouTube link".

Motion

Touch

40px tall (48px with --lg); the inner clear button is 36px with 2px to the field edge.

Content

  • Placeholders show the shape of a good answer: "https://www.youtube.com/watch?v=…". They are never the label and never instructions.
  • Units go in an addon or the label, not typed by the rider: "85" + "rpm".
  • Prefill what the app already knows (the class's YouTube link) instead of asking again (3.3.7).
