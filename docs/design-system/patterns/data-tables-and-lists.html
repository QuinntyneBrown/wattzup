Pattern

Data tables and lists

Telo Ride's collections are small and meaningful: seven maps in unlock order, up to ten riders on a board, the last few rides. So it never paginates, rarely sorts, and picks the element by the job: a table to compare, an ordered list to rank, a list to summarise, a description list for facts.

Overview

The mocks hold one real table (Profile's maps: name, stars, best time) and many lists: the Map Select path, Recent rides, the final standings, the race's live board, the class group board, the lobby's start grid, and the label-value facts in Diagnostics, Your ride and XP earned. In every one the rider's own row or result is the first thing the eye finds.

Components used: Table, List, Description list, Leaderboard, Map card, Stars, Tabs (the class length filter), Link and Section head.

Sorting, filtering, paging

  • Fixed order beats sorting when the order means something: maps go in unlock order, boards by rank, rides newest first. None of the mocks' collections is sortable.
  • Filter with tabs only when a set is big enough to browse: the Class Library's length tabs (All, 20 min, 30 min, 60 min) are the one filter.
  • No pagination. Seven maps, ten riders, four recent rides. If a list could grow (recent rides), show the latest few and a “more” link (.more-link, “All rides →”) to a page that lists them all.
  • If a table ever needs sorting, the header cell holds a button and aria-sort, and only one column sorts at a time.

Responsive behaviour

Strategy: keep collections narrow enough that they never need to scroll sideways. The maps table has three columns and fits at 360; lists put the long text in one flexible column that truncates.

A future table wider than three columns scrolls inside its own wrapper (as documentation tables do here) and keeps its first column visible; it never makes the page scroll sideways.

Accessibility

Semantics

  • The maps table keeps a thead with Map, Stars and Best, visually hidden, so every cell has a header. Header cells take scope="col".
  • Ranked lists are <ol> with a label (“Final standings”, “Group board”); the rider's row has aria-current="true".
  • Stars are one image: role="img" with “1 of 3 stars”, each star hidden.
  • The map path's line and dots are decoration (aria-hidden); the state lives in text (“, locked, your next unlock”).
  • Facts are <dl> with <dt>/<dd> pairs (grouped in <div>s where the layout needs it).
  • Live boards are not live regions. Ten rows reshuffling every second would drown everything else; the rider's own position is a readout they can reach.

Keyboard

KeyAction
TabOne stop per row: a whole map row is one link; locked rows are skipped (disabled).
EnterOpen the map's Race Setup.
Screen reader table keysMove by cell; headers are announced from the hidden thead.

Contrast

Your row: ink on volt
XP and next-unlock goal on ink
Locked goal and positions on ink

Motion

Board rows slide over 150ms; map-row thumbs don't zoom. Reduced motion removes the slide.

Touch

Map rows are at least 70px tall; table links span the cell's text (24px+ with row padding).

Content

  • Times are m:ss or h:mm:ss in tabular display numerals: 27:10, 58:03. Gaps are signed: +0:07.
  • Places are bare numerals in a rank column, ordinals in sentences: “5th of 10”.
  • Units follow a space: 14.2 km, 140 m climbing, 73 kJ, ~154 W.
  • Details join with middle dots: “Yesterday · 5th of 10 · 27:10”.
  • Dates are relative within a week: Yesterday, Mon, Sun.
  • The rider is “You” in every list.
  • XP is signed and gold: +262.
