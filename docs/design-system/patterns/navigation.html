Pattern

Navigation and page structure

Four places to browse, three flows that lead to a ride, and one rule between them: the main navigation disappears the moment you commit to a ride. Browse headers show where you are and how you're doing; flow headers show the way back; ride headers show the clock and the exits.

Overview

Telo Ride has no sidebar and no tabs at the top level. The app header carries four destinations: Home, Race (Map Select), Classes (Class Library) and Profile. Everything else is a step in a flow, and each flow screen swaps the app header for a header made for that step: a back link while you are choosing, a Leave while you wait, a clock and exits while you ride, nothing but what you rode on Results.

Components used: App header, Link (back links), Logo lockup, Level badge, Button, Skip link, Tabs (the class length filter) and Container and grid. Telo Ride uses no breadcrumb, sidebar navigation or pagination: no flow is deeper than one step back.

Mid-ride: what the header shows

Once the wheels turn, the header loses the main navigation. It holds, left to right: where you are, the bike's status (it opens Diagnostics), the clock with the total, Pause or Resume, and the exits. The custom ride adds Library (with its Leave this ride? confirmation), the workout (back to Custom Setup) and Feedback.

Back behaviour

  • A back link is a link to the parent, not history.back(): Race Setup always goes to Maps, Class Start to Classes, whoever sent you there.
  • Browser Back follows history until a ride starts. From a ride screen it does what the header's exit does: on the custom ride it opens Leave this ride?; in a race or class it pauses (solo) and asks before leaving.
  • A finished ride can't be re-entered. Results replaces the lobby and the ride in history, so Back from Results lands on Race Setup or Class Start.
  • Leaving a choice screen loses nothing, so it never asks. Leaving a ride with progress asks, unless the exit saves (End).
  • The brand goes Home from the app header only. In flow and ride headers the lockup is not a link, so a mis-tap can't abandon a ride.

Accessibility

Landmarks and names

  • The skip link comes first and targets main#main.
  • The four destinations are a nav labelled “Main”; the current one has aria-current="page" as well as its raised fill.
  • The brand link is named “Home”; the level link “Level 7, 1840 of 2600 XP”; the streak “4-day streak”; the ride status link “Diagnostics: Echelon EX-5s Connected”, which starts with its visible text.
  • Icon-only exits name their action and target: “Leave class”, “Leave race”, “Full screen”.
  • Clocks are role="timer" with a label (“Elapsed 6:52 of 30:00”) and are not live: they don't chatter every second.

Focus

After a route change, focus moves to the new page's h1 (made focusable with tabindex="-1"), so screen readers announce where the rider has landed. The header keeps the same tab order on every page that has it.

Motion

Header links change colour over --duration-fast, which is 0 under reduced motion. Route changes don't animate.

Touch

Header links are 36px tall and share the phone row, so each is about 80px wide. Mid-ride exits grow to 48px under 640px; on desktop they keep the design's 36–40px (an open question in the mocks README).

Content

  • Destinations are one word: Home, Race, Classes, Profile. The page title may differ (Race opens “Maps”), so the link names the activity and the title names the content.
  • Back links name the parent, with an arrow and no “Back to”: “Maps”, “Classes”.
  • Exits say what they do: Close (a setup with nothing to lose), Leave (a lobby or a ride), End (finish and save), Done (after Results).
  • Context lines use middle dots: “Old Town Criterium · vs Bots”, “30 Minute HIIT Cardio · Group · 9 riders”.
  • Home greets: “Evening, Sam.” The other titles are nouns.
