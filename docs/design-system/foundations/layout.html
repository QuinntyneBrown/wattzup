Foundation

Layout

Mobile first on Tailwind’s breakpoints: one shell, one centred container, an aside from 1024px, and full-bleed ride screens with the HUD floating over the world.

Overview

Telo Ride is laid out mobile first on Tailwind's breakpoints. Every screen is the same shell: a 56px header, a scrolling body, and inside it a centred container with a responsive margin. Pages are one column on phones and gain an aside at 1024px; ride screens drop the container and fill the viewport, with HUD panels floating over the world. Column count, gutter and margin are tokens that change at the breakpoints, so components read them instead of writing their own media queries.

Breakpoints

Five min-width breakpoints in rem so they follow the rider's font size. Custom properties cannot be used inside @media, so the values are repeated there (@media (min-width: 40rem)) by convention; the tokens document them.

TokenWidthTailwindWhat changes in Telo Ride
--layout-breakpoint-sm640pxsm:Header nav moves inline beside the logo; XP bar shows; card padding 20 → 28px; page titles 24 → 30px; margin 16 → 24px
--layout-breakpoint-md768pxmd:Grid goes to 8 columns, 24px gutter; the race bar shows the map and route
--layout-breakpoint-lg1024pxlg:Two-column pages (main + aside); 12 columns, 32px gutter and margin; header shows the bike; HUD panels spread out
--layout-breakpoint-xl1280pxxl:Container reaches its maximum (max-w-7xl); margins grow beyond it
--layout-breakpoint-2xl1536px2xl:Nothing new: content stays at the container maximum, centred

App shell

Every non-ride screen is .app (a full-height column, 100dvh), holding .app-header and .app__scroll, the only element that scrolls. The page inside is main.container.page: centred, margin from --layout-margin, 24px block padding (40px from 1024px). The header never scrolls away, so it needs no sticky z-index.

Layering

Layout decides where things sit on the page; Elevation decides which sits on top. In layout terms: page content is --z-base, the ride HUD floats at --z-hud over the world, menus and popovers at --z-dropdown and --z-popover, scrims at --z-overlay under dialogs at --z-modal, toasts above everything but tooltips. The app header needs no layer because only .app__scroll scrolls.

Usage

  • Start every page from the shell: .app → header → .app__scroll → main.container.page.
  • Read --layout-margin and --layout-gutter rather than repeating 16/24/32px in media queries.
  • Two-column pages switch at 1024px, never earlier: at 768px a 400px aside leaves the main column too narrow for a 4-up tile grid.
  • Use minmax(0, 1fr), not 1fr, for fluid tracks. Home's next-ride card overflowed phones in the design because its implicit track took the photo's 439px minimum.
  • Full height uses 100dvh so mobile browser chrome does not clip the bottom of a ride screen.
  • A new aside width is an area token in rem, named for its page (--profile-aside-width), not a raw value in the component.
